# 活動收藏、批次報名與本機提醒

## 使用方式

活動卡片右上角的愛心可加入收藏，收藏後以紅色填滿；「只看收藏」與既有搜尋／分類一起使用。長按卡片或點「選取」進入多選，可全選目前篩選結果、批次加入或取消收藏。重新整理或改變篩選後，已不在結果中的選取會移除。收藏限目前登入帳號；登出或重新登入會清除。

多選後點「批次報名」，App 先重新核對可報名與已報名清單，顯示可送出與排除原因。按「確認報名」後才逐筆送出，清楚列出成功、拒絕、結果不明與未送出。停止只略過尚未開始項目，目前一筆仍等待校方結果。結果不明不自動重送，同次登入的單筆與批次入口都會阻擋該活動；請重新整理「已報名活動」或至校方網頁核對。

設定 → 通知設定提供「已報名活動提醒」，預設關閉，可選活動前 1 天、1 小時或 30 分鐘。只排程明確已報名／正取且具有完整開始日期與時間的活動；候補、待審核、時間無法辨識或提醒時間已過會跳過。設定與提醒留在裝置；只有明確開啟時才詢問通知權限。

## 資料與生命週期

日期以 Gregorian、Asia/Taipei 解讀，包含校方上午／下午格式；報名截止按來源秒、分或日精度判定，不捏造時間。批次報名依校方當時回應確認資格與名額，正取已滿但仍有備取名額時保留校方判定。

活動服務使用獨立的非持久 WebKit session。換帳號及登出會取消舊讀取、阻止後續送出、清除舊畫面與收藏；送出後遇到取消或逾時保守標為結果不明。

明確載入下一頁時重建 WebView，沿用同一個非持久 cookie store；舊頁首次晚到的導覽與對話回呼不能影響新載入。同一頁內的 JavaScript 轉址仍可接續完成。結果不明的報名僅在同 session 的新查詢確認已報名後解除鎖定；清單沒有該筆時仍保留，避免校方資料延遲導致重送。

登入與 GET 讀頁可在主文件就緒後處理，不必等圖片等附屬資源；隔離 JavaScript world 的主框架標記、目前導覽識別及原有頁面解析共同確認資料。報名／修改／取消的送出仍等待完整導覽並核對校方結果。取消或逾時會阻止晚到回應重新啟動就緒檢查。Debug log 記錄排隊與頁面等待時間，不記錄帳密或完整 URL。

通知於開啟 App、回到前景、報名資料或設定變更時核對；App 關閉期間不保證同步校方異動。更新失敗保留同 session 的有效提醒。所有本機通知共用 60 個名額，包含既有未管理通知占用，優先活動、作業、校曆、上課；容量不足會顯示未安排數量。

確認取消報名時先移除該活動的快取與通知，再重新核對，讀取失敗也不會恢復已取消的提醒。升級後無法重建內容的舊通知，在該分類資料成功載入前保留並占用容量；停用提醒或登出仍會清理。容量計算先去重，狀態訊息分別顯示各類未安排數量。

## 離線驗證入口

`check-event-favorites.py`、`check-event-batch.py`、`check-event-reminders.py` 直接使用生產邏輯及隔離儲存／假通知中心，涵蓋確認前不寫入、逐筆與停止、session 競態、結果不明防重送、日期邊界、通知預算與失敗快取。既有活動、搜尋、分享、生命週期、行事曆、Widget 與 SSO 儲存檢查也需保持通過。

`check-event-registration.py` 使用真正的 WKWebView 連線本機合成伺服器，包含慢圖片、錯誤密碼、送出後核對與主文件回應前取消。兩秒慢圖片情境的首次登入與列表載入，本機單次量測由約 4.56 秒降至 0.32 秒；這是隔離環境的比較，不代表校方伺服器或真機的實際延遲。

Debug App 可啟動純合成畫面，不讀帳密或連校方：

```sh
xcrun simctl launch --terminate-running-process <UDID> dev.chienniuapp -NIUEventFavoritesFixture integrated
```

情境包含 `list`、`favorites-empty`、`selection`、`integrated`、`batch`、`reminders`、`reminders-denied`。`integrated` 使用真實列表至批次 sheet 的接線；`batch` 的三筆合成送出分別回傳成功、拒絕與結果不明。入口與資料限定 `#if DEBUG`。
